# 1.12.0 云端上传续传

本轮针对 CloudDrive2 → 局域网 WebDAV → CloudProbe → 公网云盘的使用方式。优化目标是减少公网正文重传；允许 CloudDrive2 重新提交完整 PUT。没有要求 CloudDrive2 支持 tus、Nextcloud 分块或私有续传请求头。

## 使用

1. 联通、夸克原生通道可使用“正文纯内存 · 保存续传状态”；移动及需要完整预散列的通道使用“磁盘兼容”。挂载设置优先于全局设置，修改设置前停止 WebDAV。
2. 启动 WebDAV，让 CloudDrive2 正常上传。发生网络故障时沿用分片重试、连接重建与可用的授权刷新机制。
3. CloudProbe 或 CloudDrive2 重启后，使用同一个资料目录、同一个云盘账号和目标目录，让 CloudDrive2 再次上传相同文件。内存模式边接收边逐片校验，匹配的已确认分片不再发往公网；磁盘模式完整接收并校验后恢复会话。
4. 在“云端上传续传”面板点击刷新查看任务，支持暂停、继续和放弃续传。点击继续后需要由 CloudDrive2 重试 PUT；该面板不保留本地源文件路径，也不会独立启动后台文件传输。

从 1.12.0 起，内存模式的含义是“正文不落盘，少量状态可持久化”。现有 memory 配置可直接获得此能力；内存优先在使用原生内存通道时同样支持。移动、夸克开放平台等要求预先完整散列的通道仍需要磁盘兼容。

## 恢复机制

磁盘模式收到完整文件后以 SHA-256 绑定内容。内存模式先按账号、目标父目录、目标名称、总长度及 memory 模式定位候选会话；候选相同不代表允许复用，必须逐片校验 SHA-256。分片首次发往云端前保存其指纹，收到确认后保存编号和 ETag，保存成功后才释放正文内存。未确认但已经尝试发送的分片也保留指纹，防止响应丢失后将不同内容混入旧会话。校验以有界缓冲读取，响应取消。

恢复记录存放在资料目录的 `webdav-spool/resume/`。先持久化上传会话，再上传分片；分片收到成功确认后保存编号及确认信息。磁盘写入失败会停止当前任务，不会忽略失败继续宣称该分片已持久化。每次更新通过临时文件、Sync 和替换写入；Windows 使用 DPAPI，其他平台使用私有文件权限。磁盘模式正文是当前请求的暂存文件，正常请求结束后删除；重试会清理记录所指向的崩溃残留正文。内存模式不创建正文暂存文件，只复用既有内存窗口与全局字节预算。

| 云盘 | 持久化内容 | 恢复行为 |
|---|---|---|
| 联通 | uniqueId、原上传节点、batchNo、分片大小、已确认编号和返回的 FID | 使用原会话与分片布局；重新获取当前授权，不持久化访问令牌。跳过已确认分片。 |
| 移动 | uploadTaskID、上传地址、初始返回对象 ID、分片大小和确认编号 | 继续原任务和字节范围，仅上传未确认范围；最终仍查询目录确认对象。 |
| 夸克 | task_id、upload_id、OSS 对象地址、授权上下文、回调、分片大小与 ETag | 恢复原通道和会话，重新申请分片签名，使用已保存 ETag 完成合并并核验云端内容。 |

已发送但响应丢失的分片不会被记成已确认，恢复时可能重传该片。恢复日志将“复用云端分片”单独记录；发送量统计实际公网发送字节，确认量包含复用的已确认进度。

## 会话过期与最终提交

云端保留会话的期限由服务商决定，本机保存记录不延长期限。夸克 OSS 明确返回 HTTP 404 和 `NoSuchUpload` 时，会先查询临时对象，排除已经完成上传的情况；只有未发现已完成对象才将会话视为失效。磁盘模式可用现有正文有界重建一次；内存模式将记录标为失效并结束本次请求，等待客户端完整重传后建立新会话，不尝试读取已经释放的正文。权限错误、普通 404/503 或目录查询失败都不会直接当成会话失效。

联通和移动的实际会话保留期限及完整分片查询能力尚未得到真实接口验证。遇到不能恢复的旧会话，可在界面选择“放弃续传并重传”。此操作删除本地记录，下一次 PUT 重新上传公网正文；它不会擅自删除云端临时文件。

上传完成后持久化已核验对象 ID、内容版本；备份旧目标前记录备份名。恢复时检查临时对象、最终目标和原对象身份；若最终目标已经是本任务的已核验对象，则直接确认并处理对应备份，不重传正文。若中断发生在备份旧目标之后、提交新目标之前，会在确认目标仍为空和备份身份未变后恢复原名，再走正常提交。目标或备份被其他操作修改时停止并保留证据。缺乏可靠版本信息或结果不明的情况不会强行报告成功。

## 内存模式的变化与边界

恢复时沿用原会话的分片大小，不受本次分片大小配置变化影响；新的内存预算不足以容纳旧分片时，在接收正文前拒绝并说明原因。跳过分片之前必须重新读取和校验本次局域网正文，然后释放内存。只有完整接收结束且云端结果核验通过后才能提交最终目标。

如果发现同长度的新正文与旧指纹不同，立即停止本次上传并返回冲突，保留原目标，将候选会话标为不可继续使用。下一次完整 PUT 使用新临时名称、新会话和新的分片清单，旧正文不会与新正文合并；因此文件变化可能需要额外一次局域网重传。

已完成云端上传、尚未改名提交的任务也必须先完整接收并核对重传正文，再复用已完成对象。内存状态与磁盘完整文件状态分开，不会只凭路径和大小跨缓存模式复用进度。

## 资源与并发

单条明文恢复记录最多 4 MiB，最多创建 256 个未完成记录。成功提交后删除记录；达到数量上限时要求先处理或清理旧任务。记录不按固定天数自动丢弃，避免仍有效的公网进度因本地定时清理而丢失。进程间使用系统文件锁阻止同时操作同一记录；固定 256 个锁槽限制锁文件数量，槽冲突会拒绝并发恢复，等待客户端重试。

暂停会取消正在进行的公网请求并保留已确认分片。继续只解除暂停状态，后续由客户端重新提交正文。放弃续传必须等当前任务退出，避免正在运行的线程重新写回已经删除的记录。任务清单只向已认证的本机管理界面提供目标与进度，不输出上传授权、签名或会话密钥。

## 开源与官方资料调研

官方桌面客户端多为闭源，以下结论来自公开 SDK、协议文档与开源客户端源码，不代表已逆向验证各家官方桌面软件内部实现。

- [阿里云 OSS Go SDK 上传实现](https://github.com/aliyun/aliyun-oss-go-sdk/blob/master/oss/upload.go)：保存 UploadID、文件身份、完成分片及 ETag，从未完成清单恢复上传。这里借鉴检查点设计，不将 OSS 的 ListParts 权限假定为所有网盘都提供。
- [阿里云分片上传说明](https://jaq-doc.alibaba.com/docs/doc.htm?articleId=115774&docType=1&source=search&treeId=620)：说明通过上传任务与分片查询恢复进度的机制。
- [联通开源 SDK](https://github.com/OpenListTeam/wopan-sdk-go/blob/main/upload.go)：upload2C 使用唯一上传标识和分片编号；本项目在原有分片重试基础上补充持久化。
- [OpenList 夸克驱动](https://github.com/OpenListTeam/OpenList/blob/main/drivers/quark_uc/driver.go)：上传准备、散列、顺序分片、重试和完成流程。可重试不等于已持久化至进程重启后。
- [OpenList 移动驱动](https://github.com/OpenListTeam/OpenList/blob/main/drivers/139/util.go)及[驱动说明](https://docs.oplist.org/guide/drivers/139)：移动存在多套个人云接口，不能将新 EOS 接口的能力直接套到现有 uploadTaskID 接口。
- [tusd 文件存储](https://github.com/tus/tusd/blob/main/pkg/filestore/filestore.go)：任务元数据与正文分离、恢复时核对实际状态；本轮借鉴生命周期设计，没有要求 CloudDrive2 更换传输协议。

## 验证边界

新增测试覆盖三家驱动的分片恢复、同账号/同目标/同内容绑定、不同内容与账号隔离、损坏记录保留、保存失败、系统互斥锁、CloudDrive2 风格完整 PUT 重试、上传子进程强制终止后恢复、提交阶段中断、外部修改保护、管理接口权限以及明确失效会话重建。测试以模拟云盘记录实际收到的分片和字节为依据。

这些结果证明实现和故障处理路径，不等于已经验证真实服务商的跨天会话有效期。正式使用前应在专用云盘目录进行网络中断与程序重启实测；无法确认的会话应显示限制，而不是声称必定零重传。


## 1.12.0 新增验收

新增测试覆盖纯内存完整 PUT 重试、修改后续未确认分片时拒绝混合并在下一次请求重建、已上传对象的重传校验、联通分片复用后释放窗口、保存确认失败时保留正文、取消重传时释放预算，以及强制终止真实上传子进程后的恢复。断言检查实际公网分片次数、最终云端内容、资料目录只有状态文件而没有正文文件，并检查已解密元数据中也没有正文。

还覆盖已确认记录缺少指纹时拒绝复用，以及夸克准备阶段直接返回完成对象时必须匹配本次完整正文散列。2026-10-29 使用 Go 1.26.5 在 Windows 实际运行：全量 219 个顶层测试通过、0 失败；17 个真实环境测试和 2 个子进程入口跳过，子进程入口由相应父测试实际调用。新增 8 个内存续传测试全部通过，包含强制退出后系统锁释放及恢复。rclone 模拟互操作、go vet、JavaScript 语法和 vendor 补丁检查通过；Windows/Linux CI 跟随本轮提交执行，最终结果保存在交付包 verification.json。
