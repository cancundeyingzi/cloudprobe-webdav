# 1.12.1 续传任务生命周期修补

本轮针对 `f73d824`（1.12.0）的三个复审问题：自动回退后遗留检查点、排队暂停请求写回已放弃任务、放弃任务时丢失崩溃正文清理关联。

## 自动选择上传模式

新内存任务先作为临时候选存在，准备阶段保存会话只更新候选内存。取得实际分片布局、确认内存预算可用后，才在目录配额锁内正式保存检查点并占用任务名额。准备失败或正常回退磁盘不会遗留新的 `.bin`，也不会先占一个名额再让磁盘模式申请第二个名额。

旧版本已经保存的空内存候选，在独占锁内确认没有分片、指纹、已上传对象、备份或正文关联，且没有暂停时，可撤销并按当前目标重新准备。这样旧记录中的过期 Original 不会继续阻止正常覆盖。暂停记录和有有效进度的任务不会按空候选清理。

如果旧任务已经有有效分片，但当前内存预算无法容纳原分片，则返回明确的 409，保留原任务和进度。用户可以恢复原内存预算继续，或在界面明确放弃旧任务后重新上传；该情况不会静默切换到第二个磁盘任务。

## 暂停、退役与完成

活动句柄的身份、退役状态、暂停保存及最终记录删除由同一个 checkpoint 互斥锁保护。暂停请求取得锁后必须确认自己的句柄仍是当前活动实例。退出或新阶段注册会在同一临界区退役旧句柄；终结任务会关闭该记录实例的后续写入能力。

系统文件锁在句柄退役后才释放。因此“旧暂停请求已取得句柄并排队 → 上传退出 → reset 删除记录 → 旧暂停继续”的顺序不能重新创建记录。即使同一个任务键已经开始新一轮恢复，旧句柄也不能修改新记录或移除新活动句柄。

暂停在上传结束、提交开始之间生效时，提交入口再次检查暂停状态，避免继续改名目标。进程间互斥继续由系统文件锁承担；这些规则不依赖 race detector 是否报告普通内存数据竞争。

## 放弃任务与本地正文清理

正常 reset 在独占锁内读取记录，校验 Spool 是受控暂存目录中的 `upload-*` 普通文件，先删除关联正文，再删除检查点。拒绝路径穿越、其他文件名、目录及符号链接；使用 os.Root 将删除限制在暂存目录内。

正文不存在可视为已经清理；正文被占用或清理失败时，保留检查点并返回错误，用户可以解除占用后再次操作。删除检查点本身失败时，也可以重试，不会因正文已清理而失去恢复入口。

损坏或无法解析的记录不会通过普通 reset 静默删除。界面另提供“仅移除损坏记录”，明确提示无法定位关联正文，可能仍需人工处理残留。有效记录不能借此绕过正文清理。以上操作均不删除云端临时对象。

## 回归与范围

修补前已在本机 Windows 复现：成功 auto 回退残留记录、随后同长度覆盖返回 409、255 条记录时回退返回 502，以及 reset 留下正文、清理失败仍返回成功。

新增测试覆盖正常回退、历史空候选、最后一个任务名额、有效旧分片保留并恢复、旧暂停句柄与新恢复实例隔离、退役与暂停共用临界区、提交前暂停、崩溃正文清理、异常关联路径、损坏记录显式移除，以及 Windows 文件占用解除后的重试。

本轮提取的是检查点生命周期管理层，没有重写网盘驱动。目录缓存总量、磁盘正文共享预算和增量检查点日志仍属于后续迭代。本轮验证使用模拟云盘和临时资料目录，没有执行真实网盘写入。

2026-10-29 使用 Go 1.26.5 在 Windows 本机验收：全量 230 个顶层测试通过、0 失败；17 个真实环境测试和 2 个子进程入口按条件跳过，子进程恢复测试由父测试实际执行。新增 11 个生命周期测试全部通过，rclone 模拟互操作、go vet、Windows 构建、界面脚本语法及 vendor WebDAV 补丁检查通过。对应提交的 Windows/Linux CI 与 Linux 竞态检查结果记录在交付包 verification.json。
