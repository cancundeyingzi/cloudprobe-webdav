# CloudProbe 1.6.0：总体低速恢复、无限故障重试与纯内存上传

本版将联通 WebDAV PUT 改为有界内存流水线，增加整个服务共用的总体上传低速恢复控制器，并取消可恢复上传、下载故障的重试次数上限。

## 前端设置

在“WebDAV 服务”中先停止服务，修改参数后再启动。参数保存到原有配置；密码留空保留原密码。停止服务会取消该服务的在途请求和重试。

| 设置 | 默认值 | 说明 |
|---|---:|---|
| 上传缓存方式 | 纯内存流水线 | 联通客户端上传正文不创建磁盘暂存 |
| 总体上传低速恢复 | 启用 | 所有上传共用检测及暂停开关 |
| 总体低速阈值 X | 1 MB/s | 可输入小数；1 MB = 1,000,000 字节 |
| 持续低速窗口 | 5 秒 | 排除瞬时波动 |
| 连续无效次数 Y | 3 | 连续无改善后停止主动暂停 |
| 暂停时长 | 固定 1 秒 | 应用层暂停所有上传正文，自动恢复 |
| 单文件正文缓存上限 | 32 MiB | 活跃上传及等待重试的分片一起计入 |
| 全部上传正文内存上限 | 128 MiB | 所有文件共用预算，不随文件数无限增长 |
| 提前接收目标 | 10 MiB | 与线程数、分片大小和内存预算共同决定窗口 |

服务运行时设置锁定。界面显示合计速度、统一暂停次数、连续无效次数、当前/峰值正文缓存和缓冲池已分配内存。

## 总体速度和恢复判定

检测范围是**当前 WebDAV 服务的所有上传文件、所有上传线程合计**。例如两个文件各 0.6 MB/s，合计 1.2 MB/s，X=1 时不会因单个文件较慢而触发暂停。客户端将数据交给本机的速度不计入云端上传速度。

发送速度按交给上游 HTTP 传输的文件正文计算，包含重试发送量；云端确认量另行统计。等候云端响应仍属于上传阶段。排队、退避等待、所有发送者都在等待客户端数据时，不将这段时间误判为持续云端低速。

持续低于 X 后，统一阻止所有上传正文继续读取发送 1 秒，再继续。检测使用应用层发送进度；已经进入操作系统 TCP 缓冲区的数据可能短暂继续发送。该动作保留上传会话，不强行中断已建立连接。

恢复后再观察一个完整窗口。速度达到 X，或相对暂停前改善至少 20%，计为改善并清零连续无效次数；暂停前为零时需要观察到有意义的正文进展。仍没有改善则计一次无效。连续达到 Y 后，本次服务运行显示“按带宽受限处理”，所有文件继续传输，后续新文件也不再触发主动暂停，直到重启服务或修改配置。

“按带宽受限处理”是停止反复尝试的策略，并不是证明了网络上行、运营商或网盘存在某个固定限速。错误重试与低速恢复分开，达到 Y 不会关闭故障重试。

## 纯内存流水线和背压

数据流为：WebDAV PUT 正文 → 有上限的内存分片队列 → 联通分片上传 → 云端确认 → 释放并复用缓冲区。

同一 PUT 中边接收、边上传，不要求客户端每 10 MB 断开连接。缓存满时服务器停止继续读取客户端请求正文；分片成功后腾出位置并接收后续字节。正在上传一批分片时，可以提前接收下一批，减少上游等待。

分片只在云端确认后归还内存池；发生可恢复错误时，保留相同字节、上传会话和分片编号重试。未确认分片也计入预算，因此失败不会导致缓存无限增长。缓冲池复用固定大小内存，已完成分片的元数据不随整个文件长度累积。

默认每片 5 MiB、每文件 4 个上传线程，活动分片约需 20 MiB，外加约 10 MiB 预读，实际单文件窗口为约 30 MiB，小于 32 MiB 上限。总预算按完整分片保守预留，因此最终短分片也占用一个缓冲块。调大线程数时，应相应增加内存，否则实际并发会受到缓存限制。

128 MiB 是上传正文缓冲池的预算，HTTP/TLS、日志、目录元数据、Go 运行时及下载预取另有开销。缓冲池可以保留已分配的空闲缓冲块用于后续文件，界面分别显示使用量和已分配量。

客户端供给速度不低于云端消耗速度时，预读有助于保持连续上传；客户端本身更慢时，任何有限缓冲都不能永久消除等候。

## 重试和安全边界

联通分片、移动磁盘兼容上传、下载地址请求及下载正文的可恢复故障无次数上限。网络超时、断流、HTTP 408/429/5xx 等会重试；401/403 会尝试适用的授权恢复或备用读取路线。重试等待通常为 5、10、20、30 秒，之后保持 30 秒；上游 Retry-After 指定更长时间时遵守其要求。退避时释放 HTTP 正文请求名额，仍保留未确认的上传分片。

授权仍不可用时，显示等待授权并低频再试。官网授权需要重新登录时，可以停止服务后更新。业务明确“无权限”、文件被删除、文件版本/Range/长度冲突、未知写入结果等不能通过盲目重放来解决，会明确报错并保留原内容。删除、移动、改名不因本功能而无条件重放。

重试持续到成功、请求取消、客户端断开或服务停止。第三方客户端自己的超时仍可能终止请求。纯内存缓存不提供客户端断开或程序重启后的跨会话续传。

如果网盘使整个上传会话失效，并且较早确认的分片已经释放，就需要客户端重新发送文件，不能仅靠有限内存重新播放整个文件。

## 兼容范围

- 纯内存 PUT 首先支持联通原生分片接口，需要可靠的 Content-Length。未知长度请求返回 411，不暗中落盘。
- 不支持 WebDAV 局部 PUT（Content-Range）；本功能是同一完整 PUT 内部的接收节奏控制。
- 移动当前接口需要整文件 MD5，使用前端明确选择的“磁盘兼容模式”。不支持纯内存的挂载返回 501。
- 纯内存上传不切换到需要重新读取整个文件的 OpenList 上传会话；目录、下载和原有安全回退仍保留。磁盘兼容模式保留原上传回退能力。
- WebDAV 服务内部 COPY 继续采用原有读取与重传兼容流程，可能使用磁盘暂存；客户端 PUT 的纯内存保证不扩展到该流程。
- 原有覆盖保护继续生效：先上传唯一临时名称，完成后核对目标是否被外部修改，再提交；不提前截断旧文件。

## 验证

隔离测试覆盖多文件总体阈值、统一暂停门、连续 Y 次停止、相对改善判定、客户端供给不足、内存背压、分片重试超过原次数限制、取消和资源归还、固定缓冲池、长期未确认首片时的记账上限、并发上传共享预算，以及上传受阻时目录新建与删除仍能响应。

rclone 已通过三个并发 PUT 的纯内存上传和回读验证；既有读写与容量查询回归保留。

真实联通测试在唯一专用目录内并发上传三个文件（6、11、36 MiB），再逐个下载核对 SHA256，检查没有正文暂存，结束后删除测试目录。测试会使用临时高阈值和短窗口以触发暂停，不作为真实带宽诊断；交付使用前述默认值。最终结果见随包 streaming-verification.json。
