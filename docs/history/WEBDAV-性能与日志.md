# CloudProbe 1.5.0 性能、调度与运行日志

1.6.0 补充：联通客户端 PUT 默认改为有界内存流水线，新增“总体上传低速恢复”“内存流水上传”日志及前端总速度/缓存状态。临时故障无限重试，等待递增至 30 秒并遵守 Retry-After。所有文件共享低速暂停控制器。完整行为见《内存上传与总体低速说明.md》。以下保留 1.5.0 的调度背景，整文件磁盘暂存仅适用于显式兼容模式及内部 COPY。

完整参数、候选顺序、OpenList 配置和实网结果见《多文件传输与回退.md》。

当前上传/下载分别使用文件级队列，每文件使用独立的分片并发；正文 HTTP 请求还受全局预算约束。默认同时上传 3、下载 4 个文件，每文件上传 4、下载 8 个任务，最大均为 16。总预算默认 64，统计的是 HTTP 正文请求/流，不代表必须建立 64 条 TCP 连接。

完整下载用有界窗口预取、按偏移验证和顺序输出。第三方 Range 请求不二次放大；无法确认版本或 Range 能力时降级单路或明确报错。重试与缓存不会把部分目录、混合文件版本或错误响应报成成功。

此前已实际观察到约 230—256 KiB/s 的慢速，也观察到一段高速后多个分片同步 EOF。1.4.0 的 256 MiB 对照中，HTTP/1.1 的不同样本约 0.69 和 3.38 MiB/s，HTTP/2 样本约 5.87 MiB/s，因此不能把 HTTP/2 当作唯一原因，也不能保证独立连接一定更快。

本机曾检测到 Meta TUN/Fake-IP，上传域名解析为 198.18.0.100。没有代理环境变量不等于没有经过 TUN。程序不改代理规则，也不会仅根据虚拟地址断言代理或联通固定限速。

新版真实多文件样本合计约 54 MiB，上传约 43.127 秒、并行下载约 9.662 秒；这包含排队、接口与提交耗时，并且下载阶段注入了首选地址 503 来验证回退。它是功能与恢复验证，不是官方客户端的同场性能基准。

运行记录可区分：第三方收包、本机 Write/Sync、文件排队、正文名额排队、上传分片发送及确认、下载候选失败和切换、节点分段读取、目录核验、重命名和提交。

- received_bytes 是从客户端收到的 PUT 正文。
- sent_bytes 是交给上传 HTTP transport 的正文，包含重试，不含 multipart 头。
- confirmed_bytes 是服务端成功确认的上传正文，或明确的目录核验结果。
- response_bytes 是发给 WebDAV 客户端的响应体；不能用 PUT 的几字节响应计算上传量。
- 下载读取量包含探测、重试和预取；“下载读取结束”另说明交付给调用方的字节。
- send_ms 含连接准备和正文发送，confirm_wait_ms 是发送完成到上游响应读取完成的等待，不等于服务端内部处理时间。
- queue_ms 是正文或重试名额等待；文件调度有独立事件。
- 实际上传协议、连接编号、本机端口、远端端点与复用信息单独记录。远端可能是 TUN 虚拟地址。

按请求编号查看这些阶段，可以判断慢在客户端、暂存、队列、正文链路还是上游确认。单次错误后的变化仍应结合当时日志，不对后续速度作固定承诺。
