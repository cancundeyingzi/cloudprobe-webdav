# CloudProbe 1.5.0：多文件传输与备用方案

1.6.0 变更：默认联通客户端 PUT 使用纯内存流水线；所有文件速度合计低于阈值才统一暂停；可恢复故障无重试次数上限。纯内存上传不跨会话重放到 OpenList；目录、下载及显式磁盘兼容模式仍遵守下列回退约束。新参数和最终实测详见《内存上传与总体低速说明.md》。以下验收记录属于 1.5.0。

验证日期：2026-10-25，中国标准时间。

## 参数与 wopan-open 对齐

核对的是 OpenWoPan 应用的 AppSettings，而非协议函数某个参数的默认值。

| 设置 | 默认值 | 可配置范围 |
|---|---:|---|
| 每文件联通上传任务 | 4 | 1—16 |
| 每文件下载任务 | 8 | 1—16 |
| 同时上传文件 | 3 | 1—5 |
| 同时下载文件 | 4 | 1—5 |
| 联通上传分片 | 5 MiB | 5—16 MiB |
| 下载分片 | 5 MiB，自动模式 | 4—32 MiB，可选固定模式 |
| 正文请求总并发预算 | 64 | 1—160，CloudProbe 另设的总预算 |

OpenWoPan 的默认上传任务数为 4，协议函数允许的默认上限 16 不等于应用默认值。上传、下载分别建立文件队列；超过文件数上限时可取消排队。多个文件及各分片按 FIFO 请求正文名额，目录、删除等控制操作不占正文名额。参数保存后用于该次 WebDAV 服务；修改前先停止服务。

上述任务指并发请求工作任务，不等于操作系统线程或独立 TCP 连接。HTTP/2 可以让多个任务共享一条连接。内部 JSON 字段 total_connections 是正文 HTTP 请求/流的并发预算，界面明确标注“正文请求”；真实连接编号、协议和端口继续单独记录。

联通支持完整的上述上传并发；移动上传协议仍按官方开放接口的顺序分片约定执行，文件级调度、目录回退与新版下载适用于两者。移动暂无本次真实账号，不能把联通的实测结果推及移动。

## 多文件与下载行为

上传先完整收包到本机暂存，再向云端临时名称上传、核验并提交。独立路径可并行；同一目标及其祖先目录的写入冲突及时返回 423。覆盖保留备份和失败恢复，提交前发现外部修改则停止覆盖。

完整下载在确认 Range 和对象版本可核对后，按窗口并行读取分片并顺序输出。只保留当前预取窗口，未一次读入整个大文件。实际并发也取决于文件大小和正文总预算，小文件不会强行建立 8 或 16 个请求。

上游不支持准确 Range 或缺少可核对的版本标记时，完整下载回退到单路流式读取。第三方客户端已经发送 Range 时，本机不再为这条请求放大分片并发；同一路径的多个 Range 请求共享一个文件级名额，但每条正文请求仍占总预算。上游忽略客户端所需的 Range 时返回错误，不能伪报 206。

## 自动回退范围

| 操作 | 候选方案 | 失败处理 |
|---|---|---|
| 联通目录 | 网易代理 → 联通 QueryAllFiles → 已配置 OpenList | 重新完成整次目录查询；不合并不同来源的部分页 |
| 联通正文 | 网易下载地址 → 直连 V2 → 直连 V1 → OpenList 直链 → OpenList 代理正文 | 按实际正文失败切换，避免反复选择同一个坏地址 |
| 移动读取 | 网易代理 → 移动官方开放接口 → 已配置 OpenList | 沿同一对象、目录映射尝试；独立授权仍需满足接口要求 |
| 联通上传传输 | HTTP/1.1 / HTTP/2，另有自动模式 | 自动模式在网络断流后重建连接、尝试另一协议；保持上传会话、片号和已确认分片 |
| 备用写入 | 主接口 → 已配置 OpenList | 仅能确定主操作未执行时自动换方案；结果不明先查询，不盲目重放 |

读取遇到 401、403、429、5xx、EOF 或连接重置时有有限尝试；连续失败的来源短暂冷却。冷却不会延长成永久禁用，新的读取仍可在冷却后重新尝试。外部请求取消时停止，不把取消当成需要继续重试的网络故障。

读取恢复要求大小、Content-Range 和对象版本一致。能使用不可变 FID 时按该对象读取；其他情况下检查强 ETag，或同一来源的 Last-Modified。无法确认版本时宁可终止本次读取，也不把两个不同版本拼成一个成功响应。

自动模式只调整兼容的传输协议，不凭猜测跨上传分区拼装文件。HTTP/1.1、HTTP/2 固定模式继续可选；吞吐取决于实际网络，协议切换不构成速度保证。

## 目录完整性与系统入口

保留目录、文本、压缩包、视频等真实文件条目，分页未完成、响应类型未知或缺少文件列表时不报告完整空目录。网易代理省略 fileInfoList 的兼容响应会再由直连核验。

实网发现 systemDirs 有两种形态：一种是带 ID/type 的真实目录；另一种只有 dirName、dirType、icon 等导航元数据，没有文件 ID。后者按观察到的明确字段结构识别为系统入口并单独记录，不能当作可下载、可删除的文件。无法识别的新结构仍报错。真实 files 列表继续完整处理并保留全部类型。

目录缓存带版本，避免并发修改完成后旧响应又覆盖新缓存。列表枚举与正文读取分别验证，列目录不会隐式下载所有文件内容。

## 配置已有 OpenList 服务

1. 登录云盘，选择正常工作的主挂载。进入 WebDAV 页的“OpenList 冗余服务”。
2. 为对应账号启用备用，填写服务地址、OpenList 中对应的挂载目录、API Token；目录访问密码按需填写。地址支持 HTTPS，或本机 HTTP，例如 http://127.0.0.1:5244。不能指向 CloudProbe 自身。
3. 首次启用勾选“允许创建并清理专用验证文件”。启动时由主接口创建唯一的 CloudProbe-verify-*.txt，经 OpenList 列表和正文读取核验同一目录，再清理。核验不通过不启用备用，清理失败也会明确报错。
4. 已验证配置和令牌使用 Windows DPAPI 加密保存，之后令牌留空保留原值。更换主根目录、备用根目录或认证配置后重新核验。
5. 正常运行时先使用内置方案，失败后按能力尝试 OpenList。直链不可用时还可尝试 OpenList 的 /p/ 代理正文。外部服务本身不可达、无权限或返回未知响应时，会连同前面失败原因一起报告。

该入口连接已有服务，不会自动安装 OpenList，不会把网易凭据交给外部服务；只向所填服务发送其专用 API Token。Token 不跟随正文跨域重定向，不进入运行日志或公开状态。OpenList 目录、直链、代理正文、上传、新建目录、改名、移动和删除已通过本机协议模拟；本次没有配置真实 OpenList 实例，因此未宣称完成真实外部服务验收。

备用方案需要不同的凭据或协议才能增加冗余。OpenList 的 WoPan 驱动与本工具的联通 SDK 同源，不能保证它能绕过同一上游的故障；移动的个人云等其他驱动可由 OpenList 实例自行配置，然后映射到这里。

首次映射验证需要主接口当时能上传并清理小文件。没有通过此核验的服务，不会因为主接口失败就被自动当作同一网盘使用。

## 实网验证

本次同时提交四个文件名样本：text.txt（4 KiB）、archive.zip（12 MiB）、video.mkv（18 MiB）、random.bin（24 MiB）。正文为自造数据，zip/mkv 后缀用于检查列表保留类型，并非解码或解压有效性测试。

| 检查 | 结果 |
|---|---|
| 最大同时上传文件 | 3，与默认上限一致 |
| 最大同时下载文件 | 4，与默认上限一致 |
| 实际峰值正文请求 | 12，低于配置预算 64 |
| 四文件上传总耗时 | 43.127 秒，含排队、暂存、核验和提交 |
| 四文件并行下载总耗时 | 9.662 秒 |
| 网易目录接口故障注入 | 成功切换直连并完整列出四个文件 |
| 首选正文地址 503 注入 | 成功使用联通直连 V2，记录 17 次正文请求 |
| 四文件完整下载 SHA-256 | 全部一致 |
| 第三方客户端 Range | HTTP 206，精确返回指定字节 |
| 测试目录 | 已清理 |

回退事件总数为 21。这里是有控制的故障注入，不是把测试时所有错误都解释为云盘自然故障。首轮因系统导航元数据解析过严而失败，修正并补充回归后取得上表结果；首轮目录同样已清理。

另用新版引擎重做真实 WebDAV 普通读写闭环：中文特殊字符文件名、文本读取、覆盖、复制、移动、锁、完整下载、HEAD、Range、删除均通过。移动云盘和真实 OpenList 服务尚未完成本次实网验收。
