# CloudProbe 1.7.0：界面与客户端调度说明

界面整理为五个入口：账号与登录、WebDAV 服务、传输设置、文件浏览与验证、日志中心。此版本继续使用原登录引擎和已有网盘驱动。

## 账号与登录

网易扫码、已绑定云盘、联通官网备用授权、手动 Cookie 导入以及 OpenList 接入集中在此页。Cookie 导入、接入细节等次要操作默认折叠。OpenList 的配置随下次启动 WebDAV 保存并核验，不是填写后立即生效。官网备用授权仍需先停止 WebDAV 才能修改，页面提供原因说明与服务页跳转。

## WebDAV 服务

启停与客户端地址放在顶部，基础连接参数和挂载权限分为独立卡片。WebDAV 密码仍单独管理，留空保留原校验值。服务运行期间参数只读，页面说明停止后修改，再启动生效。

## 并发与客户端要求

WebDAV 和 HTTP 没有用于通用协商“客户端线程数”或“同时文件数”的标准字段。程序不从 TCP 连接数猜测客户端配置，也不读取自造的线程数请求头。

- **客户端优先**：不再增加上传、下载文件数量上限。客户端发出多少个文件请求，就按请求处理。普通 GET 使用单路读取；客户端 Range 按实际请求的字节范围读取，不额外并行拆分。
- **服务端调度**：保留原来的文件队列与普通 GET 下载并行加速。客户端 Range 在此模式下也不会再次扩大分片并发。
- **云端上传分片并发**：普通 PUT 没有客户端线程配置；云盘要求的分片仍由服务端执行。这是独立参数，保留默认每文件 4 个上传任务，可在高级上传设置调整为 1—16。
- **资源保护**：两种模式都遵守云端正文请求预算和上传正文内存上限。达到预算会排队或减慢客户端接收。因此客户端优先不代表无限资源，也不保证任意数量请求都能同时访问云盘。

新建 GUI 资料默认客户端优先；旧资料缺少调度字段时继续使用服务端调度，以保留原配置行为。选择新模式并启动 WebDAV 后会保存。旧文件数量、下载并发等数值仍保存，在服务端调度下继续生效。旧 API 调用省略调度字段时保留原服务端默认。

配置新增 `transfer_scheduling`：`client` 或 `server`。此值属于服务端设置，不是 WebDAV 协商扩展。并行 PUT 写入同一路径仍有原有写入保护；此版本不新增客户端分块上传协议。

## 传输设置

上传与连接、下载、上传内存流水线、总体低速恢复分别归类。客户端优先时隐藏不生效的文件队列和下载分片参数。连接模式、云端上传分片任务、请求预算、缓存预算、X/时间窗口/Y 等继续保留。低速恢复按所有文件合计计算，原有错误重试及回退机制继续工作。

实时区分别显示上传文件、下载文件、云端正文请求、总体上传速度、正文缓存和低速恢复。正文请求不是 TCP 连接数，内存数字是正文缓存预算，不是整个进程占用。

## 日志中心

本次详细记录、最近 60 条 WebDAV 请求、启动与登录阶段放在同一页面的三个视图中。保留来源、路径、重试、回退和耗时等细节，并增加下载筛选、重置筛选及键盘切换。导出仍为本次完整运行日志；页面保留最近 800 条。账号授权与真实文件名称不写入随程序交付的界面截图。

## 界面验证范围

检查五个入口、表单保存与只读状态、日志切换与筛选、桌面和窄窗口布局。协议回归使用本机模拟网盘及 rclone；本轮没有为界面改动重新运行真实网盘的上传、删除等 CRUD。真实登录资料恢复和挂载启动会单独核对。移动与真实 OpenList 的实网能力不作新增验收声明。
