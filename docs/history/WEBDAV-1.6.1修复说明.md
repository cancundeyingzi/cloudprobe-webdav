# CloudProbe 1.6.1 维护修复

本版修复 1.6.0 审查确认的七项问题，保留正常使用体验。前端 HTML、传输设置脚本、日志脚本、依赖版本及原版登录桥接源码与 1.6.0 的哈希一致。原有 X/Y、线程数、内存预算、登录方式、挂载、WebDAV 用户名和密码沿用已有设置。

## 修复内容

| 编号 | 修复 | 对正常流程的影响 |
|---|---|---|
| R1 | 等分片已有可发送数据后，再申请 HTTP 请求名额，避免和内存预算循环等待 | 5 MiB 缓存、单请求等原有合法配置继续可用；仍边接收边上传 |
| R2 | 每次 HTTP 尝试的正文读取可独立取消，关闭正文唤醒等待，尝试超时同时约束正文输入 | 可恢复错误仍无限重试；单次失败保留文件缓存，停止/断开仍能取消 |
| R3 | 无稳定身份的账号不生成共享持久化键，不套用旧空身份凭据，不跨账号刷新 | 身份完整账号沿用旧标识、登录态和加密配置；仅异常身份信息被拒绝危险操作 |
| R4 | 改名响应丢失先核验目标 ID/FID、大小和名称，再决定继续或恢复 | 正常覆盖保存保持；确认提交已成功时正常完成；不确定结果保留内容与备份 |
| R5 | 使用明确响应类型及执行阶段判断重放，已经部分执行的复合移动不重新写入 | 确认未执行时继续使用 OpenList 备用；部分完成或未知结果明确报错 |
| R6 | 传播 LOCK 资源提交失败并释放锁，只在明确不存在时排他创建资源 | 正常加锁、保存、解锁不变；查询错误和创建竞争不截断已有内容 |
| R7 | 正常连接使用可清理的跟踪包装，关闭时移除连接引用，TLS 仍使用同一编号 | 日志字段和连接复用判断保持；长期重连不累积关闭连接对象 |

提交失败或核验失败也会使目录缓存失效，避免后续读取沿用旧名称。成功响应读取完毕后才清理请求上下文，避免取消尚未读完的移动接口响应。

## 兼容与错误处理

- 稳定身份的哈希算法保持原样，不重建正常账号的持久化键。
- 缺少 user_id、username、mobile 的异常账号禁止写入/恢复绑定凭据；不会把同种网盘的空身份当作同一账号。
- SDK 响应错误保留原有文字，仅增加 HTTP 状态及业务码字段。HTTP 拒绝、业务拒绝和部分执行状态分开处理。
- OpenList 配置与接口不变。明确未执行的操作继续可回退；错误消息中出现某个数字或 HTTP 文本不会自动获得重放许可。
- SDK、桥接和 WebDAV 默认地址不变。原有源文件、测试及 Windows x64 程序随包提供；旧版本交付保留用于回退。

## 验证范围

审查的七个最小复现已转为正式回归。补充验证正常凭据恢复、旧空身份隔离、请求超时后继续使用缓存、低预算完整上传、丢失提交/备份响应、外部目标占用、正常备用回退、TLS 跟踪清理，以及 LOCK 查询失败/创建竞争时保留原内容。

完整 Go、go vet、rclone 结果见 tests.txt、tests.jsonl、vet.txt。额外回归重复运行以检查并发稳定性。当前环境缺少 gcc，未启用 race detector，不将该项标为通过。

真实联通在唯一专用目录验证普通文本上传下载、覆盖保存、改名及移动、复制、锁保存及解锁、大文件、HEAD、Range 和 SHA256；并验证三个文件并发纯内存上传后回读一致。所有测试目录清理，用户原有文件未操作。真实移动账号和真实 OpenList 服务仍未配置；其回归使用隔离协议模拟。

本版不承诺消除服务商限速。总体低速暂停与错误重试保持原策略、原默认值和原界面。

## 本地依赖补丁

重新执行 go mod vendor 会覆盖本地补丁。离线构建使用 -mod=vendor；升级依赖后需重新应用 `third_party/webdav-quota.md` 与 `third_party/wopan-response-errors.md` 所述改动，再执行维护回归。
